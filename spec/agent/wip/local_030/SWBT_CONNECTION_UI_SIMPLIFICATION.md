# swbt 接続 UI 簡素化仕様書

> **状態**: 設計済み・未実装
> **対象**: GUI の swbt 設定、接続操作、ツールログ
> **関連**: [既存 GUI 実装記録](../../complete/local_025/SWBT_GUI_SHARED_SERVICE.md)、[現行の設定・CLI・GUI 仕様](../../../../docs/architecture/swbt-integration/configuration-cli-gui.md)

## 1. 概要

### 1.1 目的

ペアリングプロファイルの選択欄と独立した状態表示を削除する。接続操作の進行と接続可否は操作部の表示・有効状態で表現し、失敗の内容は既存のツールログへ集約する。

### 1.2 用語定義

| 用語 | 定義 |
|---|---|
| プロファイル | swbt がペアリング情報を保存し、次回接続に使用する JSON |
| 接続操作部 | 設定画面のボタンおよびメインウィンドウの接続メニュー |
| ツールログ | GUI の既存ログ欄。接続処理の例外を既存 logger 経由で表示する |

### 1.3 背景・問題

`DeviceSettingsTab` はプロファイルのパスを編集可能なコンボボックスとして公開している。コントローラー種別ごとの既定パスと初回作成処理はすでに存在し、通常操作で保存ファイルを選ぶ必要はない。

同画面の「状態」行には接続状態、アダプター検索結果、エラーが混在する。検索完了によって接続状態の文言が上書きされる経路もある。接続失敗は `MainWindow._fail_swbt_lifecycle()` で既存 logger に出力しており、専用のエラー表示欄は不要である。

現状は Pair / Reconnect の押下時に設定を保存する。プロファイル欄を隠した後も、画面上の選択・保存済み設定・実行中の接続先を混同してはならない。

### 1.4 期待効果

| 指標 | 現状 | 目標 |
|---|---|---|
| プロファイル選択欄 | 1 個 | 0 個 |
| 設定画面の独立した状態行 | 1 行 | 0 行 |
| 通常の接続操作 | Pair / Reconnect / Disconnect を併記 | 状況に対応する操作を表示 |
| エラーの確認先 | 状態行・ステータスバー・ツールログに分散 | 接続操作のエラー本文はツールログ |

### 1.5 着手条件

既存の非同期接続、キャンセル、手動入力の無効化を維持する。接続失敗だけでなく検索失敗・切断失敗もツールログへ到達することを確認してから表示欄を削除する。

## 3. 設計方針

GUI は既存の service / factory / session を利用する。フレームワークから GUI への依存、新しい singleton、swbt の接続方式変更は導入しない。

プロファイルの保存と再利用は維持し、GUI でのパス選択だけを廃止する。既存の設定解決を使用し、未指定ならコントローラー種別ごとの既定パスを使う。CLI の `--profile` と設定の明示パスは、CLI から操作対象を指定する現行機能として維持する。GUI 専用の別プロファイル管理層や互換 UI は追加しない。

今回の変更は既存の操作場所で行う。設定画面から接続メニューへの操作集約や、複数 Switch の接続先管理は別の変更とする。

## 4. 実装仕様

### 4.1 設定項目とプロファイル

アダプター選択・再検索・コントローラータイプ選択を残す。プロファイルコンボボックス、候補列挙、同欄から設定値を保存する処理を削除する。

| パラメータ | 型 | デフォルト | 説明 |
|---|---|---|---|
| `controller.swbt.adapter` | `str / None` | 未選択 | 既存どおり明示選択する |
| `controller.swbt.controller_type` | `str` | `pro-controller` | GUI で選択する |
| `controller.swbt.profile_path` | `str / None` | 種別ごとの既定パス | GUI 編集項目から除外し、既存設定解決で使用する |

接続操作部の登録有無判定と、実際の接続要求には同じ設定解決結果を使う。既定パスの組み立てや相対パス解決を GUI 内に重複実装しない。画面上のタイプを変更した場合は、その選択に対応した解決結果で操作部を更新する。

既存の明示パスを、画面を開く・適用するだけで消去しない。既存プロファイルの削除・移動・上書きを UI 簡素化の副作用として行わない。

### 4.2 操作部

| 状況 | 主操作 | 振る舞い |
|---|---|---|
| 未接続・プロファイルなし | ペアリング | 初回作成とペアリングを実行 |
| 未接続・プロファイルあり | 接続 | 保存済み情報で再接続 |
| ペアリング・再接続の処理中 | キャンセル | 既存のキャンセル要求を送る |
| キャンセル要求済み | キャンセル中…（無効） | 終了通知まで待つ |
| 接続済み | 切断 | 既存の入力解放・切断を実行 |
| 切断処理中 | 切断中…（無効） | 終了通知まで待つ |

登録済み・未接続の場合は「ペアリングし直す」を副操作として用意する。再接続失敗を契機に自動でペアリングへ切り替えない。

失敗・キャンセル後は接続状態とプロファイルの存在を再評価して操作部を戻す。ファイルの存在だけで接続済みと判断しない。接続成功は既存の status 判定と手動入力用 port の準備完了に基づく。

設定画面と接続メニューの判断を揃える。接続済み・処理中・マクロ実行中は接続先の選択変更を禁止し、画面の選択と生きている session が食い違わないようにする。

### 4.3 表示とログ

「状態」行と `swbt_status_label` を削除する。接続済み、アダプター件数、タイプ名、エラー本文を代替ラベルとして追加しない。内部の接続状態取得は操作制御に必要なため維持する。

検索・接続・切断の失敗は既存 logger からツールログへ出す。同じ例外を callback の各層で重複記録しない。利用者が原因を判断できる本文と既存エラーコードを確認できることを検証する。キャンセルは接続失敗として記録しない。

swbt 接続操作のエラー本文をステータスバーへ重複表示しない。アプリ全体の既存接続表示を作り直すことは本変更に含めない。

初回ペアリング開始時の Switch 側操作案内も既存ツールログを使用する。新しい常設説明欄やエラーダイアログは設けない。

### 4.4 非同期処理と設定保存

接続処理は既存 worker で実行し、widget の更新はメインスレッドへ戻す。画面破棄後の callback は既存の生存確認を維持する。

接続ボタンを押した時点のアダプター・タイプを保存し、同じ値で接続する既存の即時実行契約を維持する。設定画面の「キャンセル」は実行済みの接続操作や保存を巻き戻さない。接続操作をせず設定画面をキャンセルした場合は編集値を保存しない。

接続処理中の「適用」「OK」は無効にする。削除した状態ラベルへ警告を書き込む実装は残さない。

公開マクロ API およびフレームワークの接続 API のシグネチャ変更はない。

## 5. テスト方針

| 種別 | ケース | 検証内容 |
|---|---|---|
| GUI | 設定表示 | プロファイル欄・状態行がなく、必要な選択項目が残る |
| GUI | 初回と登録済み | 初回は Pair、登録済みは Reconnect に対応する処理を呼ぶ |
| GUI | 処理と完了 | キャンセル、切断、失敗後の操作復帰が実状態と一致する |
| GUI | 設定保存 | 未実行の編集はキャンセルで破棄し、接続操作時は表示値を使用する |
| GUI | プロファイル解決 | 種別変更・明示パス・相対パスで表示判定と要求が一致する |
| GUI / 結合 | ログ到達 | 検索・接続・切断の失敗が既存 sink 経由でツールログへ一度届く |
| GUI | 操作制限 | 接続済み・処理中の選択変更、処理中の適用、実行中の接続を禁止する |
| GUI | 画面破棄 | 処理完了前に画面が破棄されても安全に終了する |

対象 GUI テスト、変更ファイルの ruff、`uv run ty check src/nyxpy --output-format concise --no-progress` を実行する。docs 更新時は `uv run mkdocs build --strict` も実行する。実機未接続の検証を、Switch 側の接続成功確認として扱わない。
